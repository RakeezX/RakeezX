الحد المعتمد عاملان لأعمال مستقلة، مع احترام الحد الفعلي في الإعداد وعدم تزاحم النطاقات. الدمج والنشر مسار واحد متسلسل. لا تعِد مرحلة إثبات العامل الواحد لمجرد بدء محادثة جديدة، ولا تنشئ سلسلة مخطط ثم مراجع ثم مراجع آخر. استخدم حجز الموارد في مرحلته فقط وحرر ما تملكه.

إنجاز التذكرة ودليلها
نفّذ في worktree معزول من أصل صحيح، وافحص ما تأثر، واعرض Preview حين يفيد، ثم انشر ضمن التفويض وتحقق من النتيجة المنشورة. لا تجعل نهاية العامل أو تسليم PM أو انتظار محادثة بوابة جديدة. تبدأ التالية المؤهلة آليًا بعد تحرير السعة.
pending انتظار شروط البدء؛ running تنفيذ؛ delivery تسليم؛ awaiting_po نشر متحقق ينتظر القبول ويحرر السعة؛ blocked عائق موثق؛ retry_wait انتظار شرط أو موعد إعادة محدد. LOCAL_READY وPreview وexit 0 وHTTP 200 لا تثبت Production. اربط النشر بالمرشح والنسخة المدمجة ودليل المزود والأثر المنشور. CLOSED يحتاج قبولًا حقيقيًا أو اعتمادًا موثقًا ضمن تفويض قائم؛ لا تنسب للمستخدم اختبارًا لم يجره ولا تغلق طلبًا شاملًا بإصلاح جزئي.
يلتزم العامل بمخطط JSON المقدم وtaskId/runId الصحيحين والمرشح والأصل والفحوص الفعلية وبنتيجة LOCAL_READY أو BLOCKED أو NO_CHANGE. لا يكتب حالة الطابور أو يعلن نجاح الناشر. حدّث السجلات عند انتقال حقيقي واحفظ الدليل.

فحوص مرتبطة وإصلاح العوائق
نفّذ أقل فحوص تكشف ما قد يكسره التغيير وتثبت قبول البطاقة. تعديل نص أو أيقونة أو مسافة يحتاج فحص النتيجة؛ لا يستدعي تلقائيًا build كاملًا أو حزمة بيانات. أعد استخدام الدليل إذا لم يتغير الكود أو المدخل أو الاعتماد المؤثر. أبقِ الفحوص المتأثرة التي تحمي العزل والدرجات والحفظ والمزامنة والاستعادة. لا تحذف فحصًا لازمًا للحصول على PASS، ولا تعلن PASS لما لم يعمل.
عالج العوائق التقنية العادية بنفسك ضمن التفويض: مسار اختبار خاطئ، fixture غير مناسب، إعداد تشغيل ناقص، تعارض Git محدود أو نطاق بطاقة ضيق كتبه النظام. صحح الفحص وفق عقد المنتج، وحدّث النطاق أو الإعداد عبر المسار المسؤول مع سبب واضح؛ لا تحوّل هذه الأخطاء الذاتية إلى طلب إذن PO جديد. لا تغيّر المنتج ليلائم فحصًا خاطئًا، ولا توسّع الصلاحية الفعلية تحت اسم إصلاح أداة.
إذا تكرر السبب نفسه مرتين بلا دليل جديد، أوقف تكرار المحاولة المدفوعة وشخّص السبب أو اركن تلك التذكرة بعائق محدد وخطوة رفعه، وأكمل العمل المستقل. لا توقف الجميع بسبب تذكرة واحدة. أوقف التوزيع العام عند إيقاف المستخدم أو عطل مشترك مثبت أو نفاد حصة مثبت أو خطر بيانات فعلي. عند زوال عائق موثق، أصلح سبب الركن واستأنف عبر المشغّل دون إعادة الخطوات الناجحة عشوائيًا.

الصيانة الدورية المشروطة
مهمة التقرير الموجودة تعمل كل ساعة وفق جدولة Automations المتاحة. عند وجود عمل أو تقدم طبيعي تكتفي بلقطة حديثة وتقرير موجز؛ لا تُنشئ مراجعًا أو مشغّل Product آخر. إذا رُكن الطابور بسبب عائق تشغيل موثق ولا يوجد عامل نشط والناشر خامل فعلًا، يجوز لها إصلاح harness أو إعداد أو نطاق بطاقة ناقص ضمن تفويض PO القائم، ثم الاستئناف عبر المتحكم فقط. لا تعيد السبب نفسه بلا تصحيح أو دليل جديد.
جهّز التغيير قراءةً قبل الوقفة. ينفّذه scripts/ops-supervisor-v4/apply-reviewed-maintenance.mjs داخل نافذة قصيرة: ينشئ ذريًا artifacts/ops-supervisor-v4/maintenance.lock.json بهوية owner/taskId/token/PID/birth، ويعيد التحقق من الخمول، ثم ينشئ STOP جديدًا مملوكًا له. يحتفظ بالقفل حتى نهاية التغيير ويزيل STOP والقفل بمطابقة الملكية داخل finally. لا توقف عاملًا نشطًا أو تلمس STOP/STOP-REFILL أو قفلًا لغيرك. القفل القديم يحتاج إثبات غياب عملية مالكه بهوية PID/birth وحفظ الدليل؛ لا يُحذف بالتخمين.
المساعد يقبل ملفات ops المراجعة وبطاقة blocked قائمة بعد مطابقة هويتها، ولا يقبل Product SQL. الصيانة الساعية تلتزم requireNoActiveWorkers=true دون استثناء. يجوز رفع commit تشغيلي محدود مع حراسة main ووقفة الناشر، وتهيئة البطاقة لاستئناف sessionId المحفوظ. احفظ candidate والأصل والأدلة؛ المتحكم يبدأ العامل والناشر ينشر Product. لا API resume مفترض أو تشغيل Codex يدوي أو SQL/Auth حي خارج البطاقة. الصيانة لا تتجاوز rejection فعليًا ولا تحول فشلًا إلى PASS، ولا تثبت ضمان عمل 24 ساعة.
