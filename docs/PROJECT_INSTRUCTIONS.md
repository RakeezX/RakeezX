## دورة التنفيذ

- `scripts/ops-supervisor-v4/controller.mjs` يدير الطابور والتعافي، ويبدأه `start-ops.ps1`؛ الحالة الأصلية في `artifacts/ops-supervisor-v4/queue/*.json` و`ACTIVE_TASKS.json` ملخصها الحي. ملف `workflow-v5.json` يحدد `controller.activationId`؛ البطاقة الجديدة تطابقه. لا تشغّل supervisor/refill القديمين بالتوازي ولا تعِد CLOSED أو المكتمل القديم تلقائيًا.
- أكمل النتيجة المحددة: تعديل معزول → فحص متأثر → Preview مفيد عند الحاجة → نشر ضمن التفويض → تحقق أثر النسخة المنشورة. لا توقف الدورة لتسليم روتيني إلى PM أو انتظار محادثة أخرى، ولا تنشئ عامل تشخيص ثم عامل تدقيق ثم عامل تسليم للمشكلة نفسها.
- بعد نشر مثبت، تنتقل التذكرة إلى `awaiting_po` وتبدأ التالية المؤهلة دون انتظار PO. الانتظار لا يعني CLOSED، وإغلاق التذكرة يحتاج قبولًا حقيقيًا أو اعتمادًا موثقًا ضمن تفويض قائم؛ لا تنسب إلى PO اختبارًا لم يُجرِه، ولا تغلق طلبًا شاملًا بإصلاح فرعي. العائق الخاص يُركن بسبب محدد وتستمر الأعمال المستقلة.
- افحص ما قد يكسره التغيير فقط. النص والأيقونة والمقاس يحتاجون فحص النتيجة لا حزمة جديدة. لا تكرر PASS لنفس الكود والمدخلات، ولا تربط تعديل عرض بفحوص بيانات غير متأثرة. أبقِ حماية العزل والدرجات والحفظ والمزامنة والاستعادة إذا مسّها التغيير. حافظ على Demo parity حيث يوجد مقابل منطقي.
- أصلح عيب الأداة داخل المهمة، وعند تكرر السبب مرتين بلا دليل جديد اركن العائق بدل دورة مدفوعة أخرى. `maxWorkers=1` لإثبات التسليم، ثم 2 للأعمال المستقلة بعد نجاح التحقق؛ يقرأ المشغّل التغيير دون restart. مسار دمج/نشر واحد دائمًا. استعمل حلول المشروع والمكتبات المرخصة المناسبة دون إعادة بناء المعمارية لميزة صغيرة.
- احمِ تغييرات المستخدم والمرشح والموارد المملوكة فقط. لا reset أو force-push أو قتل عمليات مجهولة أو حذف قفل غير مملوك أو جرد وتجميد كل الفروع. توقف المهمة المخطئة في النطاق الخطأ، واحفظ الدليل؛ لا تفرض تدقيقًا شاملًا على كل التذاكر بسببها.

## بيانات المنتج

- الإعداد القابل للتراجع بالكود وبيانات Demo الاصطناعية يختلف عن تشغيل تغيير حي. نشر كود يغيّر الكتابة أو الحذف أو الصلاحيات يمس البيانات حتى لو لم يعدّل العامل سجلًا يدويًا. Auth/RLS/schema/migrations/Owner Guard/Sync/Delete/Restore/Backup/scoring وصلاحيات RAKEEZ Admin تحت تفويضها المحدد والفحص المتأثر.
- لا تغيّر حسابات المعلمين أو سجلات الطلاب والدرجات، ولا تطبق migration أو RLS أو حذفًا حيًا أو إرسالًا حقيقيًا بلا تفويض مطابق. لا تعِد migration المطبّق لـN77، ولا تمس Outbox التاريخي لـN58. A/B الاصطناعي محدود بالهويات والغرض المعتمدين. حافظ على هوية الطالب وتاريخه والمالك ومنع عودة المحذوف والعزل والمزامنة.
- RAKEEZ Admin صلاحيات خادم محددة، لا محرر قاعدة بيانات خام ولا service-role في المتصفح. التشخيص بالبريد/واتساب يلتزم allowlist: لا أسماء طلاب أو درجات أو حضور أو معرّفات خاصة أو tokens أو SQL خام أو UA كامل.
- تسمية الواجهة «فصول»؛ نطاق N86 واضح «الفصل الحالي / كل فصول الصف» بلا تكرار شروح. N87 إنجازات فعلية وكؤوس/ميداليات وبطاقة يختار المعلم محتواها. استيراد N12 V1 أسماء فقط؛ الدرجات اختيار مستقل في N90 ولا تُعد منفذة أو أولوية نشطة تلقائيًا. لا تعِد فتح تذكرة مغلقة لصيانة فرعية جديدة.

## الاستمرار والإبلاغ

- التشغيل تحت Abody عند تسجيل دخول Windows، بنسخة واحدة وتعافٍ مستقل عن بقاء المحادثة. لا وعد بالتشغيل قبل تسجيل الدخول. احفظ الجلسة والمرشح والخطوة؛ راجع العملية والنشر قبل تكرارهما بعد عطل.
- السرعة Standard ونماذج المشغّل المعتمدة حسب الحاجة؛ لا Fast أو مراجعات مدفوعة متكررة أو reset أو اشتراك جديد. عند نفاد الحصة احفظ التقدم وانتظر الإتاحة، وعند STOP جديد لا تبدأ تذاكر؛ لا تقتل كتابة سليمة لتلبية ساعة قديمة.
- فرّق المحلي وPreview وProduction؛ exit 0 أو HTTP 200 لا يثبت النشر. سجّل نتيجة موجزة مع المصدر والرابط والدليل والعائق، وحدّث السجل مرة عند انتقال حقيقي. أبلغ عن أثر منشور أو عائق يحتاج قرارًا، لا تقارير تُعيد فتح فحوص منتهية. المقياس تسليم مفيد وزمن التعطل وإعادة العمل، لا عدد الجلسات.
