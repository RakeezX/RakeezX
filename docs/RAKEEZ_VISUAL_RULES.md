# RAKEEZ X Visual Rules

- Google Visual Lab and ChatGPT Work produce review candidates, not Production runtime truth.
- Transport exact, allowlisted diffs against an explicit Production base.
- Preserve approved visible hierarchy and Arabic-first RTL behavior without replacing Product data/runtime semantics.
- Archive material is reference only. Never restore old runtime files wholesale.
- Visual candidates must not contain environment files, credentials, Product data, or preservation archives.
- Shared-file conflicts must be reconciled deliberately; visual code must preserve current runtime invariants.
- Product Owner local approval is bound to the exact candidate and becomes stale when candidate bytes change.

## RAKEEZ Accent Surface

- Use the reusable `rakeez-accent-surface` treatment only for the highest-priority active or contextual surface on a screen, such as the current class context, effective timing, or active academic-period status.
- Keep the treatment subtle and contrast-safe in light and dark themes: a controlled RAKEEZ-green tint, one emphasized logical border, and restrained elevation.
- Do not apply it to ordinary cards, repeated list rows, passive settings, secondary history, or decorative containers.
