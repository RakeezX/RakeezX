## Root cause and bounded change

`src/lib/workspaces.js` finalizes the registry receipt as `{protocol, restoreId, manifestHash, completedAt}`. Its account descriptor puts that exact ownerless receipt in leaseGeneration. `resolveWorkspaceForBoot` independently reads the existing account IndexedDB device receipt, verifies its explicit owner and matching registry fields, and binds the authenticated owner to the deterministic database. The previous shared class guard nevertheless required `restore.ownerId === owner`, denying every such genuinely restored ownerless teaching. The prior unit test fabricated a registry receipt containing ownerId; the previous browser proof used provisioning, so neither caught this defect. Earlier hosted deployment evidence does not establish Product success, and PO rejection remains authoritative.

Only application change: `src/store.js` accepts an absent registry owner field after its existing immutable owner/workspace/DB, live session/cloudAccess, lease and class/parent guards. An explicitly present owner must match (including rejection of null); the device receipt still must explicitly name the owner. Protocol must now also equal the registry protocol, alongside restoreId, manifestHash and completedAt. No UI/navigation, Sync, scoring, student storage, N103 deletion, Auth, RLS, schema, service or startup dependency changed.
