# N88 — تجربة دعوة الطالب، ببيانات افتراضية فقط

الحالة: نموذج عميل اصطناعي؛ **N88 يبقى OPEN**. لا تسجيل دخول حقيقي، ولا خدمة دعوات أو نشر بيانات طالب. نقطة الأساس: `ea623168458e3708519ec0a5f4f1ac1b49580cdb` (HEAD وorigin/main عند بدء العمل، وأكده git ls-remote origin refs/heads/main قبل الحفظ). لا دفع أو نشر من العامل؛ دليل المصدر المنشور مسؤولية الناشر المستقل.

## التجربة الحالية

افتح مساحة Demo القائمة ثم `#/n88-invite-lab`. كل الأسماء والأنشطة والدرجة أمثلة ثابتة في `src/lib/n88-invite-lab.js`، مستقلة عن سجلات Demo نفسها. لا يقرأ العرض سوى نوع مساحة العمل من المتجر. الحسابات والمساحات الأخرى لا ترى المثال؛ ترى رسالة عدم الإتاحة ورابط العودة. يُعاد فحص الحاجز في كل تفاعل.

يحاكي زر «تجربة فتح رابط الدعوة» النتيجة المتوقعة من رابط/QR؛ لا يولّد QR قابلًا للمسح ولا رابط مشاركة أو دعوة حقيقية. البديل اليدوي `DEMO-ONLY` مجرد placeholder معلن، ليس سرًا أو إثبات هوية. عرض الطالب للقراءة فقط، دون إرسال أو تعديل أو روابط لسجلات الطلاب. حالة التجربة في DOM الحالي وتزول بالمغادرة/التحديث؛ لا حفظ للرمز ولا بيانات شخصية أو طلبات شبكة من التفاعلات. لم تُغيّر Auth أو RLS أو الخادم أو المخطط أو درجات/حسابات حقيقية.

## قرار الوصول الحقيقي المقترح — يحتاج إذنًا وتنفيذًا مستقلين

- يُنشئ الخادم وحده سر دعوة عشوائيًا بمولّد تشفيري وبقوة لا تقل عن **128 bit**. لا سر عميل مولّد أو رقم طالب متسلسل أو رمز قصير بديل. يخزن الخادم hash للسر فقط مع owner وفصل وطالب موثّقين، ووقت انتهاء قصير وصريح وحالة استعمال/إلغاء؛ لا يخزن السر بصورته الخام.
- يتأكد الخادم من ملكية المعلم للفصل والطالب ومن أهليته للإصدار. يسلم المعلم الدعوة الفردية عبر تسليم خاص موثوق بعد التحقق من الطالب؛ الاسم أو رقم WhatsApp وحده لا يثبت الهوية، ولا تُنشر الدعوة في مجموعة. لا رسائل تلقائية مفوّضة بهذه التجربة.
- المطالبة single-use ذرية على الخادم: فحص hash بزمن ثابت، انتهاء وإلغاء وملكية وربط صحيح، ثم استهلاك مرة واحدة وإصدار جلسة محدودة. سباق جهازين لا ينتج جلستين. رسائل الفشل عامة لا تكشف وجود الطالب، مع rate limiting حسب الدعوة/المصدر وسياسة محاولات مناسبة دون تسهيل حجب الطالب.
- قناة HTTPS مع منع تسرب السر إلى referrer/analytics/سجل الخادم. عند تصميم الرابط، يُنقل السر من fragment إلى طلب مطالبة مخصص، ويزال فورًا من شريط العنوان/history؛ يبقى عابرًا في الذاكرة فقط. لا سر في localStorage أو IndexedDB أو logs أو URL query أو telemetry. تحتاج تفاصيل الجلسة إلى مراجعة مستقلة؛ المقترح cookie آمنة HttpOnly/Secure/SameSite مع حماية CSRF وتدوير الجلسة، لا bearer طويل الأجل محفوظ بالعميل.
- صلاحيات الطالب read-only محدودة، مناسبة للعمر وبأقل حقول ممكنة: منشورات المعلم المصرّح بها لذلك الطالب وملخص تقدمه فقط. RLS/الخادم يفرضان owner + class + student ولا يثقان بمعرّفات يرسلها العميل. لا كشف زملاء أو سجلات المعلم أو write/submission/storage. تؤخذ موافقة ولي الأمر/متطلبات العمر والخصوصية ضمن عقد لاحق قبل التفعيل.
- إلغاء الدعوة قبل استخدامها وإلغاء الجلسات بعدها، وإعادة الإصدار تُبطل القديمة. تبديل الطالب/الحساب يمسح العرض والذاكرة ويلغي الجلسة السابقة ويعيد التحقق؛ لا انتقال إلى مساحة المعلم. انتهاء العضوية أو سحب نشر المهمة يمنع القراءة فورًا وفق عقد جلسة محدد، ولا تخزين offline لمحتوى خاص في هذا النطاق.
- قبل أي تفعيل: PO منفصل وصلاحيات أدوات دقيقة للخدمة/Auth/RLS/schema، واختبارات ربط المالك، منع وصول طالب لطالب آخر، انتهاء/إلغاء/إعادة استخدام، سباق المطالبة، معدل المحاولات، تبديل الحساب وتسرب الأسرار. هذه الوثيقة تصور قرار وليست إثبات تنفيذ أمني.

## التحقق الفعلي وحدوده

- `node tests/n88-student-invite-lab-browser.mjs`: ثمانية سيناريوهات في التطبيق الحقيقي عبر loopback HTTP في متصفحات معزولة جديدة: 320/390/768/1280 × light/dark. الدليل المختصر: `tests/n88-student-invite-lab-browser.json`.
- رابط المحاكاة والرمز الصحيح/الخاطئ، RTL، عدم overflow، أهداف لمس 44px، تركيز لوحة المفاتيح والرجوع ومسح الإدخال، صفر طلبات أثناء التفاعل وعدم تغيير localStorage/sessionStorage وجميع مخازن IndexedDB، مع getter traps تثبت عدم قراءة حالة المتجر الخاصة، ورفض handler قديم بعد تبديل نوع المساحة، ورفض نوع account في المتجر الحقيقي بسياق اصطناعي دون تسجيل حساب. هذا ليس اختبار حساب حي.
- `node --test tests/n88-student-invite-lab.test.mjs`: حواجز نوع المساحة، مصدر ثابت بلا صلاحيات بيانات/شبكة، وتنفيذ handler عامل الخدمة الحقيقي في VM مع تعذّر الشبكة لإرجاع shell ووحدات المسار وCSS المخبأة. أضيفت الوحدتان إلى SHELL؛ لا تغيير سياسة cache.
- فحص المتصفح يعطل Service Workers وفق المسار المعزول المصرح به؛ يثبت استمرار handlers المحملة عند قطع الشبكة، **ولا يدّعي اعتماد PWA مثبت أو cache حي**. فحص VM محدود بمسار cache المتأثر. لا Preview أو اختبار خدمة حي أو دليل Production من هذا العامل.
- تحقق syntax و`git diff --check` على النطاق. تُغلق سياقات المتصفح ومحركه والخادم المحلي المملوك في finally؛ لا حجز للمتصفح المشترك مطلوب في هذه المرحلة المحلية المعزولة.
