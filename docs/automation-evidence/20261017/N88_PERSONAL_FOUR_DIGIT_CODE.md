## Current implemented contract

- Cryptographically random **1000..9999**, exactly **9,000** theoretical codes, ASCII output, first digit 1..9. Repeated digits are allowed. No pattern blocklist, sequential fallback, padding or truncation. Generator defaults to Node `randomInt(1000,10000)`; its draw injection is used only for deterministic tests.
- Service, client and actual form normalize Arabic/Persian digits using the existing adapter. Validation is `^[1-9][0-9]{3}$`. `1000`/`9999` and their digit equivalents succeed; `0007`/`0074`/`0000`, three/five digits and whitespace fail. The input deliberately has no four-character maxlength that could silently truncate a five-digit paste to a valid code.

Existing conservative HMAC tombstones also reserve retired values: at most **9,000 lifetime distinct issuances per owner** in this proposal, with earlier refusal possible. Every session remains scoped to its current class/enrollment/revision and expires after 8 hours. A membership/scope change refuses old sessions; the same code/bookmark can create a fresh session for a separately verified current membership. An ended relationship without replacement, name clone, new student or foreign owner does not inherit access.
