## UNKNOWN, refusal and retirement

A bounded original command (at most 16 KiB) is reserved and read back in this tab's sessionStorage before dispatch, keyed by exact owner/Teaching/Section/subject/Term/session/lease/context. It contains the exact original request ID, revisions and decisions; for a manual task it necessarily includes its teacher-authored payload for the existing exact status contract. It contains no bearer, student roster, grade values, received projection or credentials. It is not a success receipt or authorization. Storage failure refuses dispatch. No arbitrary user storage is cleared.

Only the trusted callback immediately before the real fetch marks a dispatch. A local validation/storage/owner/queue refusal before that marker is `not_started` and removes only its own reservation. A timeout, bad response/body, lost ACK or possible commit after that marker stays UNKNOWN. Public exception properties cannot forge this provenance. Listing/refreshing cannot clear UNKNOWN or enable another write. Reload restores the same original command, and `status` submits it only inside the service's read-only status envelope; there is no automatic resend. Exact receipt + fresh state + unchanged binding/membership/source/revision/choices are required by the existing reconciliation helper before settling.

Source/class/account/session/route changes dispose old views and requests; delayed responses cannot repopulate them. Original student storage-event retirement, signout, navigation and failed-read handling remove private content. Unrelated source hints are not adopted by another context. A changed source/membership that prevents safe reconciliation stays UNKNOWN rather than being guessed rejected or retried.
