## State and recovery

The controller is the sole writer of queue state. The wrapper writes only one attempt checkpoint, stdout JSONL, stderr and the structured final response. The published receipt belongs to the deterministic publisher. `ACTIVE_TASKS.json` is a current summary and `controller-events.jsonl` is the transition journal; the process inventory and birth identity determine actual liveness.

`pending → running → delivery → awaiting_po` is the normal path. `awaiting_po` releases the execution slot and does not mark Product CLOSED. The records helper updates the existing Product status/PO review block while preserving the user's notes. A later actual entry in the Closed Product ledger can change the runtime to `closed`. Record write failure never retries the model or publisher; the same record transition is retried independently.

Each launch has an immutable attempt specification and a UUID run ID. Codex's `thread.started.thread_id` is saved as the exact session ID in its checkpoint and queue record. Resume passes that ID explicitly, never `--last`, and preserves the existing worktree and candidate. A restarted controller adopts a living wrapper or Codex child only after matching its PID, birth time and invocation. It waits for owned descendants as well. PID reuse does not make an unrelated process an owner. If process inventory is unavailable, the controller writes the issue and starts no additional worker.

Quota/auth/network failures keep the session/worktree and use durable backoff. Quota/auth backoff starts at 15 minutes and is bounded at 60 minutes; network backoff starts at 15 seconds and is bounded at 5 minutes. These are local retry choices, not claims about OpenAI limit reset times. Only one saved-session probe runs while a shared model outage is active. They do not consume the two implementation-failure attempts. Two actual implementation failures park that card and leave independent cards eligible.

A running wrapper owns its temporary browser/integration/live resource through the existing lease path. During delivery, the owner is the controller's verified identity. A prior controller's integration lease can be reclaimed only for the same activated task after the exact former process is absent. An ended worker's phase lease can be reaped only for that same activation/task/run, with a saved controller absence record that includes its exact owner and known descendants, followed by another native process-identity check. The reaper itself requires the verified live controller. Unknown legacy leases remain recorded. A pending provider receipt holds the one delivery lane so a later push cannot overtake its production observation. On controller restart, only the publisher journal is resumed, with no new Codex worker for an already prepared candidate.

Cards explicitly marked `executionMode: local` or `synthetic` can use `budgetMinutes` and `idleMinutes`. A useful-progress clock tracks JSON events and content fingerprints of scoped files/Git HEAD; a wrapper heartbeat alone does not reset it. For the first cards, N92 is 20 minutes total/8 minutes idle and N91 is 45/15. On an expired budget, the controller first saves the exact owned process identities, then stops only matching PID/birth identities and their observed descendants, waits for a fresh absence check, and resumes the saved session once. A second implementation/watchdog failure parks the card. Any `liveAuthorizationRef`, live-mutation resource or live execution mode disables this automatic interruption. A malformed checkpoint becomes a specific incident; it cannot trap an ended worker in `running` forever.

STOP or STOP-REFILL now pauses admission/worker/publication starts while the controller remains alive and refreshes its summary. Removing a future pause marker resumes the controller automatically. The current older marker is handled once at the authorized cutover by the parent.

## Permissions and trusted completion

Fresh execution uses `codex exec --sandbox danger-full-access -c approval_policy=never`. Resume uses the installed command's supported `-c sandbox_mode=danger-full-access -c approval_policy=never`, with `ProcessStartInfo.WorkingDirectory` and the exact session positional argument. A read-only attempt stays read-only. `--approve-for-me` is absent because this installed CLI selects workspace-write for that option.

PowerShell 5.1 compatibility matters: prompt input is explicitly UTF-8 bytes through `StandardInput.BaseStream`; this .NET runtime lacks `StandardInputEncoding`. Atomic checkpoint replacement uses `[NullString]::Value`, because `$null` was converted to an invalid empty backup filename in the native probe. stdout/stderr files allow concurrent reads. All argv values are quoted using Windows argv rules; prompts are not shell commands.

The required final response is the schema saved at runtime in `worker-result.schema.json`: task/run identity, `LOCAL_READY | BLOCKED | NO_CHANGE`, full candidate/base SHA, worktree, changed paths, scoped checks and blocker details. A model's final message alone cannot mark production. The controller checks the actual Git HEAD, declared-base ancestry, tracked cleanliness and the approved path scope before delivery. Every name in a card's `requiredChecks` must have a corresponding `PASS` entry; `NOT_RUN` does not satisfy it. This validates the existing affected-check receipt, without rerunning the check. The first cards use `scope`/`syntax` and `responsive_layout`/`card_navigation`, respectively.

The publisher owns integration/current-main checks, deterministic metadata/build, non-forced push, provider observation and served-source verification. FAST copy work uses the publisher's metadata-only path; STANDARD uses its single integration build. A worker's text `PASS` is not passed as a trusted build-cache key. Build/merge failures are returned as bounded correction context to the same original Codex worktree/session; the integration worktree is diagnostic context, not a replacement candidate identity.

`awaiting_po` requires the host publisher's candidate-to-published ancestry, exact provider head/deployment, verified immutable and Production assets, and a changed Product source asset. Production metadata currently contains a content fingerprint, not a Git SHA. The observer compares actual source bytes. The only allowed normalization is the tested, narrowly matched Cloudflare JSD insertion in HTTP-200 `index.html`; it retains the raw hash and also proves the normalized hash equals the expected Git blob. A generic HTML cleanup is not accepted.
